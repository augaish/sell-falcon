# الدفعة المصطنعة — دليل التحقق والتشغيل

الحالة: **جاهزة ولم تُشغَّل.** لا ربط، لا مفاتيح، لا طلبات مدفوعة حتى توافق على كل خطوة.

## ما هي

طلبان إلى Claude API بمحتوى مؤلَّف لمنشأة غير موجودة («مركز الأفق الوهمي للياقة»، نطاق ‎`.example`):

| # | النوع | النموذج | `max_tokens` | الغرض |
|---|---|---|---|---|
| 1 | استخراج | Haiku 5.5، effort منخفض | 2000 | مجال المنشأة وملخص من نص مصطنع |
| 2 | مسودة | Opus 5.5، effort متوسط | 4000 | رسالة تعارف من حقائق مصطنعة |

لا اسم جهة حقيقية، لا نص موقع حقيقي، لا قراءة مواقع، لا بحث، لا إرسال رسائل. العنوان والرقم المصطنعان في النص يُحذفان قبل الإرسال كما في المسار الحقيقي. الغرض: تسجيل ردّين حقيقيين يُختبر عليهما الموصّل، ومطابقة أول تكلفة فعلية.

## التكلفة

| | القيمة | مصدرها |
|---|---|---|
| المتوقع | 0.02$ إلى 0.06$ | أحجام مفترضة: 400–800 توكن إدخال، 300–1500 إخراج للاستخراج، 1000–3000 للمسودة |
| الحجز | نحو 0.08$ | معادلة `spend.py` على `max_tokens` كاملًا، وعلى عدّ المزوّد لتوكنات الإدخال قبل كل طلب |
| حد مشروع الدفعة في النظام | 0.15$ شهريًا ويوميًا | `synthetic_batch.CAP_USD` |
| إن حُصرت المعالجة في الولايات المتحدة | كل ما سبق ×1.1 | |

**كيف يُحسب الإدخال.** نداء العدّ المجاني يحمل الطلب كما سيُرسل: النص ومخطط المخرجات (`output_config`) معًا، فالحجز يشمل توكنات المخطط. ما لا يغطيه العدّ:

- العدّ تقدير من المزوّد وقد يختلف قليلًا عن المحسوب فعلًا. إن زاد الفعلي على الحجز يُسجَّل ويُوقف المشروع، بعد وقوع التكلفة.
- توكنات التفكير تُحسب إخراجًا، وهي داخل `max_tokens`، فالحجز يغطيها.
- المزوّد الوهمي يعدّ بطول النص ولا يعرف المخطط؛ أرقام التشغيل الجاف لا تصلح قياسًا للإدخال.

**الحجز والحدود ليست سقفًا مضمونًا.** `max_tokens` يحد الإخراج عند المزوّد، وعدّ التوكنات يحدد الإدخال، فالتجاوز هنا غير متوقع، لكن لم يُختبر شيء من هذا على المزوّد الحقيقي بعد. كله من رصيد Max؛ لا شراء ولا شحن تلقائي.

## الخطوة 1 — تحقق أنت (قراءة فقط، لا تضغط «Link organization»)

أحتاج منك ستة أجوبة:

1. **claude.ai ← الإعدادات ← الفوترة:** هل يظهر قسم «API credits»؟
2. هل هو **مربوط مسبقًا**؟ وباسم أي منظمة؟
3. تاريخ تجديد دورة الفوترة.
4. إن كانت لديك منظمة Console: في **platform.claude.com/settings/billing** تحت «Promotional credits»، ما **المبلغ وتاريخ الانتهاء**؟
5. في الصفحة نفسها: هل توجد **وسيلة دفع**؟ هل **الشحن التلقائي** مفعّل؟ هل يوجد **رصيد مشترى**؟
6. هل في تلك المنظمة مساحات عمل أو مفاتيح لمشاريع أخرى؟

## الخطوة 2 — المنظمة والحدود المقترحة (للموافقة؛ لم يُنفَّذ منها شيء)

تذكير من وثائق Anthropic: الخطة تُربط بمنظمة واحدة، وتغييرها لاحقًا يحتاج الدعم.

**المقترح (إن لم يكن الرصيد مربوطًا، وليست لديك منظمة تبني فيها):**

| البند | القيمة المقترحة |
|---|---|
| المنظمة | منظمة Console جديدة باسم `Sell Falcon`، تُنشأ أثناء الربط |
| وسيلة الدفع | لا تُضاف |
| الشحن التلقائي | مطفأ. لا رصيد مشترى |
| مساحة العمل | جديدة باسم `sf-synthetic` (الحدود لا تُضبط على المساحة الافتراضية) |
| حد إنفاق المساحة الشهري | أصغر قيمة يقبلها Console، ولا تزيد عن 1$ |
| منطقة المعالجة للمساحة | الافتراضي (عامة)، إلا إن قرر المختص حصرها |
| المفتاح | واحد، محصور بمساحة `sf-synthetic`، باسم `sf-synthetic-batch`. يُعطَّل بعد الدفعة |

**إن كان الرصيد مربوطًا مسبقًا بمنظمة:** لا نغيّر الربط. نضيف فيها مساحة العمل والمفتاح بالحدود نفسها. وإن كان فيها وسيلة دفع أو شحن تلقائي أو رصيد مشترى فنفاد رصيد Max لا يوقف الطلبات، ويبقى الاعتماد على حد المساحة وحدود النظام؛ أخبرني لنقرر.

لاحقًا، للتجربة الحقيقية: ثلاث مساحات (`sf-wtexcellence`، `sf-calgym`، `sf-oshhh`) بحد ومفتاح لكل منها.

## الخطوة 3 — بعد موافقتك: أنت تنشئ، وأنا لا أرى المفتاح

أنت تنفّذ الربط وتنشئ المساحة والحد والمفتاح. المفتاح لا يُكتب في المحادثة ولا في المستودع.

**مكان التشغيل — توصيتي: جهازك.** هذه الجلسة السحابية لها مسار خاص إلى `api.anthropic.com` لا أتحكم فيه، فلا أستطيع أن أؤكد مسبقًا أن طلبًا يخرج منها يُحسب على منظمتك. الموصّل يثبّت العنوان ويتجاهل متغيرات البيئة، لكن الفحص المجاني أدناه هو ما يحسم ذلك فعليًا.

على جهازك، داخل مجلد المشروع:

```bash
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
```

```bash
export SELLFALCON_ANTHROPIC_KEY='ضع المفتاح هنا'
```

```bash
export SELLFALCON_EXPECT_ORG='معرّف المنظمة من Console'
```

```bash
export SELLFALCON_EXPECT_WORKSPACE='wrkspc_...'
```

الثلاثة إلزامية. غياب أي منها يوقف `--preflight` و`--live` قبل أي اتصال، ولا يُلتقط مفتاح من متغيرات `ANTHROPIC_*` الموجودة على الجهاز. معرّف المنظمة يظهر في إعدادات المنظمة في Console، ومعرّف مساحة العمل في صفحة مساحات العمل.

## الخطوة 4 — فحص مجاني قبل أي طلب مدفوع

```bash
python synthetic_batch.py --preflight
```

يرسل عدّ توكنات لكلمة واحدة (مجاني)، ويقارن معرّف المنظمة ومعرّف مساحة العمل اللذين أعادهما المزوّد بالقيمتين المتوقعتين، ويطبع `"ok": true` أو `false`.

التحقق نفسه يجري آليًا داخل التشغيل الحقيقي: مرة قبل الدفعة، ثم قبل **كل** طلب مدفوع ضمن نداء العدّ الذي يسبق الحجز. معرّف مختلف أو غائب يوقف الطلب قبل إرساله بلا حجز ولا تكلفة. ويُفحص الرد المدفوع نفسه أيضًا؛ إن جاء بتعريف آخر تُسجَّل تكلفته ويُوقف المشروع، لأنه لا يُستدرك.

لم أتأكد بعد أن نداء العدّ يعيد الترويستين فعلًا (الوثائق تذكرهما لردود الـAPI عمومًا). إن لم يعدهما فسيقف التشغيل عند هذا الفحص ولن يُرسل شيء، ونعالج ذلك حينها.

## الخطوة 5 — التشغيل (بموافقتك المنفصلة)

```bash
python synthetic_batch.py
```

تشغيل جاف بمزوّد وهمي **في مجلد بيانات مؤقت يُحذف بعده**: لا يكتب في سجل النظام ولا يستهلك من حد الدفعة الحقيقية. الدفعة الحقيقية لها مشروعها («دفعة مصطنعة — حقيقية»)، وترفض البدء إن وُجد في سجله أي تكلفة كتبها مزوّد آخر. كل صف تكلفة يحمل اسم المزوّد الذي كتبه، والتقرير يعلّم صفوف المزوّد الوهمي.

```bash
python manage.py paid on
```

```bash
python synthetic_batch.py --live
```

```bash
python manage.py paid off
```

- يتوقف عند أول فشل. أي طلب غير محسوم يوقف مشروع الدفعة حتى تسوّيه.
- الردّان يُحفظان في `recordings/` (خارج المستودع افتراضيًا). فيهما المحتوى المصطنع والاستهلاك ومعرّف الطلب ومساحة العمل، بلا مفاتيح.

## الخطوة 6 — المطابقة

أرسل لي مخرجات الأمر ومحتوى `recordings/`. ثم:

1. أنقل الردّين إلى `tests/fixtures/recorded/` وأشغّل `tests/test_recorded.py` عليهما.
2. نقارن لكل طلب: توكنات الإدخال والإخراج والتكلفة في سجل النظام مقابل صفحة **Cost** في Console لمساحة `sf-synthetic`، وما نقص من الرصيد الترويجي. Console قد يتأخر في العرض.
3. أي فرق فوق 10% يوقف الانتقال للتجربة الحقيقية حتى يُفهم سببه.
4. يُعطَّل المفتاح.

## ما اختُبر وما لم يُختبر

- **اختُبر محليًا:** 63 اختبارًا للموصّل والدفعة يعمل فيها الـSDK الحقيقي على ناقل وهمي: شكل الطلب، قراءة الاستهلاك، تصنيف الأخطاء، عدم إعادة المحاولة من الـSDK، تجاهل متغيرات البيئة، الفحص المجاني، والدفعة نفسها بمسارها الحي.
- **الردود في تلك الاختبارات مصطنعة**، مكتوبة على شكل أنواع الـSDK، وليست مسجَّلة من المزوّد.
- **لم يُختبر:** أي طلب حقيقي، هل يعيد نداء العدّ ترويستي التعريف، مطابقة العدّ للمحسوب فعلًا مع المخطط، سلوك الرصيد عند النفاد، وحد مساحة العمل.
